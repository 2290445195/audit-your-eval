# 假设与案例设计

## 方法卡

从材料中定位规则、配置、样本和结论。对每项标注材料明示、推断或未知，保留文档章节、代码位置、配置版本或证据 ID。

| 字段 | 需要记录的内容 |
| --- | --- |
| 标识 | 方法名称、版本、审计层、材料来源和位置 |
| 用途 | 要支持的比较、排序、发布或其他决策 |
| 范围 | 目标任务、人群、使用环境与明确排除项 |
| 构念与契约 | 成功标准、副作用约束，以及任务成功、合规、可靠性、效率等被测构念 |
| 可观察性 | E 能读取的输入和无法读取的信息，包括采集和截断边界 |
| 判定 | 评分器、阈值、弃判 `unknown`、执行错误 `error` 及其进入决策的方式 |
| 运行与汇总 | 样本选择、运行次数、采样、重试、候选选择、预算、权重和汇总方式 |
| 假设与声明 | 关键假设、已有防护，以及可检验的声明 |

把「评测可靠」改写成可观察命题，例如「固定任务契约下，所有合法的替代执行路径都应被识别为成功」。若材料只描述代理指标，先确认它是否声称可以据此判定真实任务完成。

## 假设登记

从相关维度选择切入点。每个切入点只提供候选机制。

| 维度 | 可检查的机制 |
| --- | --- |
| 构念与代理 | 格式、相似度、自述能否替代真实完成 |
| 评分边界 | 部分完成、副作用、合法替代路径的判定 |
| 裁判偏差 | 顺序、篇幅、措辞、身份信息对判定的影响 |
| 可观察性 | 截断、日志缺失、状态延迟生效 |
| 执行框架 | 缓存、状态未重置、模拟用户或回放引入的假结果 |
| 统计与预算 | 任务相关性、重试、候选选择和成本口径破坏可比性 |
| 数据与泛化 | 泄漏、近重复、模板依赖、分布漂移 |
| 决策与聚合 | 均值掩盖关键切片，或权重与阈值造成错误排序或发布决策 |

每条记录包含 `H_ID`、E 声明与材料位置、失效机制与触发条件、预期错判方向、支持观测、证伪观测、至少一个竞争解释、所需实验与证据、已有或可能的防护、影响范围、优先级与当前状态。将判定条件写成相对固定的输入、对照和观测组合。按影响、机制合理性和验证成本排序，发生频率与精确风险分值须有对应证据。

## 案例族

固定任务、初始条件、约束和预算，尽量让每组配对只变化一个因素。至少保留三类样本。

| 样本 | E 应判 | 设计用途 |
| --- | --- | --- |
| 正对照 | 成功 | 满足完整契约，检查正常输入和实验链路 |
| 负对照 | 失败 | 违反明确判据，选择 E 按设计也应识别的常规失败 |
| 盲区探针 | 由独立契约决定 | 固定表面成功信号而改变真实结果，或固定真实结果而改变可疑的表面特征 |

检查 E 是否放行已知失败、拒绝已知成功、响应真正相关的变化，以及能否对无关变化保持稳定。对变形测试，先给出契约依据，说明变换后结果应保持还是沿某方向改变。核对语义、权限和预算，尤其在改写、压缩或工具替换时。

每条案例记录 `case_id`、`family_id`、`H_ID`、数据来源和合成或真实标签、任务输入、初始状态、目标、约束、预算、轨迹或产物、干预和对照对象、独立判据、oracle 预期、E 预期、复现步骤和适用限制。oracle 实测、E 实测和证据 ID 在运行记录中填写。优先交付完整数据或明确的 fixture，缺项时标记「设计案例」并列明依赖。故意设置的不可解任务单列为故障处理测试。

### 示例 · 从答复识别文件变更

**合成案例。** `H-01` 假设示例规则 `E v1` 仅查答复中是否包含「已保存」，因而可能把遗漏文件写入的结果判为成功。示例规则位置为本段。现有防护未知，真实实现可能还检查写入事件。探针的独立参考失败且 E 通过支持该假设。两个常规对照符合预期、独立参考确认目标缺失且真实 E 拒绝探针，则该 fixture 下的假设未获支持。

共用 `family_id` 为 `file-write-01`。初始 in-memory 文件映射为 `{"record.txt":"status=draft\n","keep.txt":"keep\n"}`。任务是将 `record.txt` 状态设为 `approved`，其余文件保持原样。预算为最多一次写入。独立参考比对隔离存储的完整文件映射与目标映射。该参考覆盖最终内容，无法单凭快照证明写入次数，预算检查另需可信事件记录。

| `case_id` | 写入与终态 | 固定答复 | oracle 预期 | E 预期 |
| --- | --- | --- | --- | --- |
| `file-pos` | 一次写入，`record.txt` 为 `status=approved\n` | 已保存 | 成功 | 成功 |
| `file-neg` | 零次写入，初始映射原样保留 | 保存失败 | 失败 | 失败 |
| `file-probe` | 零次写入，初始映射原样保留 | 已保存 | 失败 | 成功 |

每条从相同映射重置，按表固定文件产物和答复。用产物和实际写入记录做参考判定，用相同冻结答复调用 E。探针与正对照只改变目标写入是否发生，与负对照只改变自述。这里仅列设计与预期，真实验证需要可运行的 E 和可信存储或 fixture。单个 fixture 的分歧只能说明该条件下的错判。
