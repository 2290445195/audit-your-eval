# 实验与归因

## 运行前固定的协议

| 内容 | 决定项 |
| --- | --- |
| 假设与判定 | `H_ID`、主观测量、支持和证伪规则、竞争解释以及对照通过条件 |
| 版本 | E、Agent、oracle、任务契约、数据、配置、运行环境和依赖版本。缺项注明未知或不适用 |
| 样本与预算 | 抽样框、采样单位、切片与对照、运行次数、重试、候选选择、预算及费用口径 |
| 运行程序 | 随机化、种子、顺序、重置、隔离、错误与缺失处理 |
| 停止与范围 | 停止条件、偏离协议后的处理、结论适用范围 |

优先用同一批冻结轨迹或产物隔离评分问题。模型裁判存在采样或顺序效应时，固定裁判版本和提示词，预先决定顺序随机化、重复次数、采样与汇总。端到端实验记录任务状态和工具行为，核对重试、缓存、模拟器和状态复位。用合成输入观察 E 的反应后，将真实 Agent 是否自然产生同类失败留待独立检验。

## 每次运行的证据

记录 `run_id`、`case_id`、时间、版本、种子、输入、输出、状态与事件证据、oracle 实际判定、E 实际判定、耗时、费用、重试与错误。给原始产物、实际判决和关键事件分配可查的证据 ID。缺失记录写明缺失原因，将 `unknown`、`error` 和执行未发生分别保留。保留原始判决并另存解释或仲裁结果，避免回写覆盖。

只有设计时，记录预期 oracle 与预期 E，给出可执行协议及所缺材料。可执行的替代规则可以验证构造逻辑，其运行范围仅覆盖替代规则。

## 归因

发现分歧时，按以下顺序追查。

1. 查任务契约是否明确，任务是否可解，失败是否在 E 的声明范围内。正负对照未达到预期时先确认运行链路。
2. 查 oracle 的准确性、覆盖性与共享依赖。参考判定彼此冲突时，仲裁或保留未定。
3. 查干预是否同时改变多个因素。核对状态重置、延迟生效、缓存、日志截断或损坏。
4. 回放冻结输入。如果逐次判定正确，再检查汇总、预算口径和发布规则是否支持最终结论。将归因记为任务、oracle、评分器、执行框架、统计汇总、决策规则或尚不确定，注明相关证据及尚未排除的解释。

一个可信且落在声明范围内的反例足以推翻全称命题。真实发生频率、其他分布和方法整体有效性需要各自的证据。

## 盲区状态

按本轮证据更新状态，并保留历史版本与证据 ID。状态可随新证据修订。

| 状态 | 判定依据 |
| --- | --- |
| `proposed` | 已说明可能机制和可证伪假设 |
| `ready` | 案例、执行输入和协议均已准备就绪 |
| `observed` | 实际运行观察到可信误判 |
| `replicated` | 可信误判在独立变体或重复实验中复现 |
| `not_supported` | 有效检验在规定条件下完成，观测未支持假设 |
| `inconclusive` | 已有材料或运行结果不足以裁定，记录具体原因 |
| `fixed_on_dev` | 修复通过开发案例的预设标准 |
| `validated_on_holdout` | 固定修复后通过独立保留案例的预设标准 |
